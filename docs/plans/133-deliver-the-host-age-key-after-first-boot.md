# Deliver the host age key after first boot

This ExecPlan is a living document. The sections Progress, Surprises & Discoveries,
Decision Log, and Outcomes & Retrospective must be kept up to date as work proceeds.
If durable project context changes, update or create ADRs in docs/adr/ in the same change.


## Purpose / Big Picture

After this change, an operator can create a cloud VM from a secret-free Nagare image, then run one
documented command to stream that context's age private key over Identity-Aware Proxy (IAP) SSH.
Nagare installs the key as root with mode `0400`, re-runs sops-nix decryption, and starts the existing
Tailscale autoconnect unit without exposing the key in an argument, log, repository, image, or
temporary file. IAP is Google Cloud's authenticated TCP tunnel and is available before the host has
joined the private Tailscale network.

The operator can see the result in three ways. `nagarectl host place-age-key --context prod
--key-file /secure/path/prod-host-age-key.txt` reports a verified checksum and successful secret
activation; `nagarectl --context prod server status` and `nagarectl --context prod doctor` report the
host age key as ready; and `/run/secrets/tailscale/authkey` exists while the host joins the tailnet.
A NixOS virtual-machine test proves the complete missing-key-to-decrypted-secret transition without
touching a real cloud project.

## Surprises & Discoveries

- Observation: the pinned sops-nix module can install regular secrets through
  `sops-install-secrets.service`, but Nagare does not set `sops.useSystemdActivation`; depending on
  the NixOS user-management mode, decryption can therefore remain an activation script with no
  service to restart after a post-boot key handoff.
  Evidence: `nixos/modules/nagare-host.nix` currently sets only `sops.defaultSopsFile`,
  `sops.age.keyFile`, and the Tailscale secret. The pinned sops-nix revision
  `c591bf665727040c6cc5cb409079acb22dcce33c` in `nixos/flake.lock` exposes
  `sops.useSystemdActivation` and the `sops-install-secrets` oneshot.

- Observation: the pinned nixpkgs Tailscale unit interpolates `cat <authKeyFile>` directly into
  `tailscale up --auth-key`. A missing decrypted file therefore still invokes `tailscale up` with
  an empty key, which explains the interactive login URL in IR-18.
  Evidence: the nixpkgs revision `eaad089433ca2bb662274377d33df3d0e51ef28b` in
  `nixos/flake.lock` defines that script, and `nixos/hosts/nagare-01/tailscale.nix` supplies
  `config.sops.secrets."tailscale/authkey".path` as `authKeyFile` without a pre-start guard.

- Observation: the existing IAP wrapper retries a command after transport failures, but a generic
  command consuming inherited stdin cannot replay bytes already consumed by a failed attempt.
  Evidence: `scripts/iap-ssh.sh` implements retry around `_do_ssh`; its `recv-file` operation
  deliberately reopens/truncates its destination for each attempt. Sending a key needs the symmetric
  source-file operation so each retry reopens the operator's key file without staging a copy.


## Decision Log

- Decision: implement the supported post-boot placement option requested by IR-18, using the existing
  IAP SSH transport, rather than introducing Secret Manager delivery at boot.
  Rationale: the image already contains the operator's public SSH key and IAP is deliberately the
  break-glass path before Tailscale works. This keeps the private key in operator custody, adds no
  project IAM or secret-resource lifecycle, and addresses the contradictory “before first boot but
  not in the image” documentation directly.
  Date: 2026-09-14.

- Decision: put installation, metadata checks, sops reactivation, and Tailscale restart in one
  host-side `nagare-host-age-key` helper generated by the NixOS module.
  Rationale: the host module knows the configured `nagare.host.ageKeyFile` even when it is not the
  default path. The same helper gives the CLI, status probe, and VM test one behavior instead of
  duplicating a hard-coded path on the workstation.
  Date: 2026-09-14.

- Decision: stream the key body directly from the operator's source file to the final configured
  host path. Reopen the source file for each IAP retry; never put the body in argv, stdout, stderr,
  an environment variable, an image, a repository, or a local/remote staging file.
  Rationale: this is IR-18's requested confidentiality boundary. Direct final-path installation is
  not atomic, so first placement is the normal path, a matching key is an idempotent no-op, and
  replacement of a different existing key requires `--force` plus an explicit interruption warning.
  Date: 2026-09-14.

- Decision: make `sops-install-secrets.service` the retryable activation boundary, order the
  Tailscale autoconnect unit after it, and add a pre-start check that prints `age key missing` before
  the upstream script can call interactive `tailscale up`.
  Rationale: restarting a well-defined oneshot is narrower and more observable than rebooting or
  running a full NixOS activation. An `After=` relationship preserves the Tailscale unit's own
  explicit failure message even when sops decryption failed; a hard `Requires=` would skip the
  Tailscale process and hide that message behind “dependency failed.”
  Date: 2026-09-14.

- Decision: extend the existing `nagarectl server status` inventory and `doctor` remediation rather
  than adding host-secret state to `nagarectl platform status`.
  Rationale: platform status compares release identities, while server status already performs one
  best-effort IAP host probe for disk health. Age-key readiness is operational host health and can be
  collected in the same SSH round trip without changing the release-compatibility JSON contract.
  Date: 2026-09-14.

- Decision: amend local ADR 5 during implementation; do not create a new ADR or amend ADR 11 unless
  implementation changes the guarded NixOS-generation activation boundary.
  Rationale: ADR 5 owns context-specific host inputs and currently says `host init` records only the
  age-key path. It is the durable home for the separate, explicit private-key handoff. Restarting
  secret and Tailscale units does not activate a NixOS generation and therefore does not weaken ADR
  11's guarded-switch rule.
  Date: 2026-09-14.

- Decision: accept IR-18 and point it to this plan at plan creation; change it to completed only when
  the implementation and verification in this plan are complete.
  Rationale: the bidirectional link establishes ownership without claiming that the defect is fixed.
  Date: 2026-09-14.

## Context and Orientation

The defect and required verification are recorded in
[IR-18](../improvement-requests/host-age-key-has-no-first-boot-delivery.md). A Nagare cloud host
keeps an age private key at the path configured by `nagare.host.ageKeyFile`, normally
`/var/lib/sops-nix/age-key.txt`. “age” is the encryption identity used by sops; the encrypted
`secrets.yaml` is safe to version, but only the matching private identity can decrypt it. sops-nix
is the NixOS integration that turns that encrypted file into runtime files under `/run/secrets`.
The first such secret is `/run/secrets/tailscale/authkey`, which lets the host join the operator's
Tailscale private network, or “tailnet,” unattended.

`nagarectl host init` is implemented in `cli/nagarectl/app/Main.hs` and
`cli/nagarectl/src/Nagare/Host/Config.hs`. It creates a context-owned flake under
`${XDG_CONFIG_HOME:-$HOME/.config}/nagare/hosts/<context>/` containing public host configuration and
an encrypted secrets file. It intentionally records only the on-host key path. The key itself must
remain outside every repository and image. `cli/nagarectl/src/Nagare/Target.hs` resolves a context
to a `TargetProfile` carrying the GCP project, zone, instance name, and deploy user needed for a
remote operation.

`scripts/iap-ssh.sh` is the supported IAP-tunnelled SSH transport. It works around an OpenSSH 10.x
macOS failure by starting `gcloud compute start-iap-tunnel`, routing OpenSSH through `socat`, and
retrying transient tunnel errors. It sources `scripts/lib/target.sh`, whose
`_require_target_project` check refuses when the selected context and Google Cloud project do not
agree. The new CLI path must set `NAGARE_CONTEXT` explicitly in the child process so a command-level
`--context` selection is also the context checked inside the script. The existing `scp` operation
creates a remote file and therefore is not the delivery primitive for this secret.

`nixos/modules/nagare-host.nix` owns the reusable host configuration. It sets
`sops.defaultSopsFile`, `sops.age.keyFile`, and the `tailscale/authkey` declaration.
`nixos/hosts/nagare-01/tailscale.nix` passes that decrypted secret to nixpkgs'
`tailscaled-autoconnect.service`. Today there is no explicit missing-key guard. On the observed host,
the missing file produced a `cat` error and the Tailscale CLI printed an interactive login URL.
The NixOS module is the correct place to generate a root-only helper because it sees the effective
age-key path after all operator overrides.

`cli/nagarectl/src/Nagare/Ops/Status.hs` gathers the `nagarectl server status` inventory.
`probeDisk` already executes one best-effort IAP SSH command and returns `UNKNOWN` rather than
crashing when the VM cannot be reached. `cli/nagarectl/src/Nagare/Ops/Probe.hs` owns the `Probe` and
`ProbeStatus` types and the table renderer. `cli/nagarectl/src/Nagare/Ops/Doctor.hs` attaches a
remediation command to each non-OK probe and makes `doctor` exit nonzero on `FAIL`. The age-key
observation should join the same host round trip, preserving the best-effort behavior for an
unreachable VM while grading a confirmed missing or invalid key as `FAIL`.

`nixos/flake.nix` contains the repository's NixOS-specific checks, including
`pkgs.testers.runNixOSTest` virtual-machine checks. These checks are not part of the root flake's
native checks, so the new VM check must be invoked explicitly from the nested flake as well as
evaluated by `nix flake check ./nixos --no-build --all-systems`. `cli/nagarectl/test/HostSpec.hs`
holds host-focused Haskell tests, while the broader probe and doctor cases live in
`cli/nagarectl/test/Spec.hs`. `nix/checks/scripts/nagare-operator-tools.sh` and
`nix/checks/scripts/nagare-clone-free-platform.sh` exercise installed and hermetic CLI behavior.

The user-facing contradiction appears in `docs/user/secrets.md`,
`docs/user/onboarding-bring-your-own-project.md`, and `docs/user/host-image-and-boot.md`. The latter
two currently require placement before the same `infra-up` operation that creates and immediately
boots the VM. `docs/user/provisioning-with-pulumi.md`, `docs/user/reference.md`, and `CHANGELOG.md`
also need the new bootstrap behavior and command. Historical release notes remain immutable.

Three local architecture decisions are relevant. [ADR 5](../adr/0005-use-context-owned-host-flakes-for-operator-nixos-inputs.md)
puts operator inputs in context-owned flakes, keeps the private key out of those flakes, and records
only its on-host path; it must be amended with the explicit handoff boundary. [ADR 9](../adr/0009-assert-the-active-context-project-on-every-cloud-mutating-path.md)
requires a cloud operation to derive its project from the selected context and fail closed on
disagreement; the IAP delivery must preserve that invariant. [ADR 11](../adr/0011-host-activation-is-guarded-and-self-reverting.md)
reserves NixOS-generation changes for the guarded host-switch path; this plan restarts only the
secret installer and its dependent service. ADR 13 was inspected because it governs private
operator material, but it needs no amendment: the private key remains outside both public and
private repositories. No cross-repository ADR is needed.


## Plan of Work

### Milestone 1: establish the retryable host-side boundary

Change `nixos/modules/nagare-host.nix` to accept `pkgs`, set `sops.useSystemdActivation = true`, and
generate an installed `nagare-host-age-key` program with `status` and `install` subcommands. The
program embeds the safely shell-escaped effective `cfg.ageKeyFile`; callers never supply a remote
path. `status` must always produce exactly one tab-delimited record and exit zero so a health probe
can distinguish `ready`, `missing`, and `invalid` from transport failure. `ready` means a non-empty
regular file owned by root with mode `0400`; include its SHA-256 digest but never its contents.

`install --sha256 <hex> [--force]` runs only as root. It validates the digest syntax, creates the
parent directory root-owned and non-world-readable, and inspects any existing key before consuming
stdin. A matching installed digest is not rewritten. A different digest refuses unless `--force`
was supplied. For a missing key or confirmed replacement, stream stdin directly through GNU
`install` to the configured final path with owner/group root and mode `0400`; do not use `mktemp`,
`tee`, shell variables, command substitution, or an intermediate path for the key body. Verify the
installed digest and metadata, restart `sops-install-secrets.service`, require a non-empty
`/run/secrets/tailscale/authkey`, and restart `tailscaled-autoconnect.service`. If checksum
verification fails, remove the unusable partial target and return a message that tells the operator
to retry. Output may name the path, digest, and service results, but not key text.

Augment `systemd.services.tailscaled-autoconnect` in the same module. Add ordering after
`sops-install-secrets.service` and a pre-start script that first checks the configured age key, then
the decrypted Tailscale auth-key file. It must fail with the literal phrase `age key missing` when
the private key is absent and must fail before nixpkgs' upstream autoconnect script invokes
`tailscale up`. Do not add a hard dependency that suppresses this pre-start diagnostic.

Add a `host-age-key-delivery` `pkgs.testers.runNixOSTest` check to `nixos/flake.nix`, extracting the
test module into `nixos/tests/host-age-key-delivery.nix` if that keeps the flake readable. The VM
must boot with no file at the configured key path and with an encrypted test secret that cannot yet
be decrypted. Generate a disposable age identity and encrypted YAML during the VM test rather than
checking a reusable private key into Git. Override the Tailscale program body with a test-only
oneshot so the test exercises Nagare's ordering and pre-start guard without contacting Tailscale.
First assert the autoconnect journal contains `age key missing` and contains no interactive login
URL. Then pipe the disposable key through the exact `nagare-host-age-key install` interface, assert
root/root `0400`, assert `/run/secrets/tailscale/authkey` contains the test value, and assert the
test autoconnect unit succeeds. Printing the canary secret or private identity fails the test.

Milestone acceptance: the focused VM derivation exits zero and its log visibly contains a missing
state followed by a ready state and successful decrypted-secret assertion. The checked-in tree
contains no age private key.

### Milestone 2: deliver through IAP with one CLI command

Extend `scripts/iap-ssh.sh` with
`send-file <instance> <local-path> -- <remote-command...>`. Its per-attempt function opens a new IAP
tunnel, runs SSH with the existing identity and proxy options, redirects the named local file to SSH
stdin, and tears down the tunnel. Put the file redirection inside the retried function so each
attempt reopens the source from byte zero. Do not implement it in terms of `scp`, do not buffer the
key in a shell variable, and do not copy it to a temporary path. Update the script's usage comment
and dispatcher. The retry helper's temporary stderr file is permitted because it contains transport
diagnostics only and never receives stdin.

Create `cli/nagarectl/src/Nagare/Host/AgeKey.hs`, expose it from
`cli/nagarectl/nagarectl.cabal`, and add it to `cli/nagarectl/test/HostSpec.hs` coverage. Local
inspection must reject a missing, directory, unreadable, empty, or malformed file; require exactly
one non-comment line beginning `AGE-SECRET-KEY-1`; and compute SHA-256 over the exact bytes that the
transport will reopen. Do not print or return the body from diagnostics. The pure command builder
must select the context's instance and construct only:

```text
send-file <instance> <local-key-path> -- sudo -- /run/current-system/sw/bin/nagare-host-age-key install --sha256 <digest> [--force]
```

Use the absolute remote program path so root does not depend on the SSH or sudo `PATH`; every
remote word other than the validated hexadecimal digest is fixed by Nagare.

Add `HostPlaceAgeKeyOpts` and `HostPlaceAgeKey` to `cli/nagarectl/app/Main.hs`, parsed as
`nagarectl host place-age-key [--context NAME] --key-file PATH [--force]`. Resolve the active target
once, reject local-mode contexts without invoking a tool, resolve the packaged IAP helper through
the active platform workspace, and run it with a child environment whose `NAGARE_CONTEXT` equals
the resolved context. Preserve the rest of the environment; do not change the parent process
globally. A nonzero helper exit must retain its useful stderr while the CLI adds a concise operation
label. Success says the context and host are ready but never echoes file content.

Tests must use an injected/fake transport that records argv and hashes the supplied file itself.
Assert that explicit context selection chooses the correct instance/project context, `--force` is
absent by default and present only when requested, the key body is not a member or substring of any
argument or environment override, local mode invokes nothing, and all validation failures occur
before transport. Include an installed-command or packaged-payload assertion that the shipped
`scripts/iap-ssh.sh` advertises and dispatches `send-file`.

Milestone acceptance: Haskell tests pass; a fake-transport command test receives the same SHA-256 as
the source and no secret-bearing argument; and the VM test still passes through the host-side
interface the CLI invokes.

### Milestone 3: make missing state visible and actionable

In `cli/nagarectl/src/Nagare/Ops/Status.hs`, replace the disk-only remote probe with one host probe

`missing` or `invalid` as `StatusFail`, and malformed/missing probe output as `StatusUnknown`.
`--skip-vm` returns an unknown age-key probe alongside the existing skipped disk probe without

Add pure parser/grading cases to `cli/nagarectl/test/Spec.hs`. In
`cli/nagarectl/src/Nagare/Ops/Doctor.hs`, give the `host age key` probe a specific explanation and

already selected by the doctor invocation. Assert that confirmed missing state makes doctor exit 1,
ready state exits 0 absent other failures, and unreachable IAP remains a warning rather than a false
claim that the key is absent.

Milestone acceptance: focused tests show `FAIL host age key age key missing ...` in server status,

## Validation and Acceptance

The change is accepted only when each behavior below is observable.

A VM booted with no configured age key reaches an SSH-accessible state. Its
`tailscaled-autoconnect.service` fails quickly, its journal contains `age key missing`, and neither
the journal nor serial output contains a Tailscale browser-login URL. `nagare-host-age-key status`
returns a parseable `missing` record; it does not mistake an unreachable machine for a missing key.

Given a valid local age identity, this command selects the named context even when another context
is current:

```bash
nagarectl host place-age-key --context labs --key-file /secure/labs-host.agekey
```

The only secret-bearing channel is SSH stdin. The process arguments contain the local path,
instance, fixed helper name, expected SHA-256 digest, and optional `--force`, never the key body.
The IAP wrapper reopens the original file for a transport retry and creates no secret staging file.
The remote result is a non-empty key at the module-configured path with owner/group root and mode
`0400`; the verified digest equals the exact local bytes.

After placement, `sops-install-secrets.service` succeeds, `/run/secrets/tailscale/authkey` exists,
and `tailscaled-autoconnect.service` reaches success without an interactive step. Running the same
command with the same key is safe and re-establishes the service state without rewriting the key.
A different existing digest is rejected before writing unless `--force`; forced replacement is
documented as interruption-sensitive and verifies before any decryption attempt.

`nagarectl --context labs server status` renders confirmed absent or invalid metadata as a `FAIL`
row whose detail includes `age key missing` or the exact metadata defect. `nagarectl --context labs
doctor` exits 1 and prints `nagarectl host place-age-key --key-file <private-key-file>`. A ready key
renders `OK`. IAP/tool failure renders `UNKNOWN`/warning and does not falsely say the key is missing.

An operator following the revised bring-your-own-project guide can generate the host flake and
encrypted secret, build the image, boot the VM, deliver the private key through the documented
command, and observe tailnet join before relying on Tailscale access. No step asks them to place a

## Idempotence and Recovery

Local validation and remote status run before any mutation. If the remote key is already byte-for-
byte identical, the helper does not rewrite it; it re-runs secret activation and Tailscale startup,
so retrying after a service or transport failure is the normal recovery. If the IAP tunnel fails,
`send-file` reopens the original source file on its next bounded attempt. A partial first placement
cannot pass SHA-256 verification and is removed, leaving an explicit missing state that is safe to
retry.

A different installed digest fails closed before stdin is consumed unless the operator passed
`--force`. Because the no-temporary-file requirement rules out atomic rename from a staged secret,
a forced rotation can lose the previous key if the connection is interrupted after the final path
is opened. Before using `--force`, retain the old and new key in the operator's external backup and
ensure `secrets.yaml` is decryptable by the new recipient. On interruption, rerun the new key with
`--force`; if new-key decryption fails, re-place the backed-up old key with `--force` and restore the
old encrypted secrets. The helper must state this boundary in `--help` and failure output.

Restart failure does not remove a checksum-verified key. Fix the encrypted file or service error and
rerun the same placement command; matching-key behavior retries activation. `server status` and
`doctor` are read-only. The VM test generates disposable key material during its run and the Nix
test sandbox cleans it up.

Documentation and ADR edits are ordinary versioned files. OKF log additions are append-only; if a
validation command fails, correct the concept and rerun rather than deleting prior log history. The
unrelated dirty worktree files noted in Concrete Steps belong to other tasks and must remain intact.


## Interfaces and Dependencies

No new Haskell or cloud dependency is required. `cli/nagarectl/nagarectl.cabal` already depends on
`bytestring`, `crypton`, `memory`, `process`, `directory`, `filepath`, and `text`. Use those packages
for exact-byte inspection, SHA-256, child process construction, and diagnostics. Do not change
dependency bounds. Mori has no registered sops-nix project (`mori registry search sops-nix`
returned no match), so the plan verified behavior against the exact upstream revisions pinned in
`nixos/flake.lock`; implementation must keep using those pins and must not traverse `/nix/store`.

`cli/nagarectl/src/Nagare/Host/AgeKey.hs` should expose a small secret-free model. Equivalent names
are acceptable only if the responsibilities remain separated:

```haskell
data LocalAgeKey = LocalAgeKey
  { path :: !FilePath
  , sha256 :: !Text
  }

data RemoteAgeKeyStatus
  = AgeKeyReady !FilePath !Text
  | AgeKeyMissing !FilePath
  | AgeKeyInvalid !FilePath !Text
  | AgeKeyStatusUnsupported

inspectLocalAgeKey :: FilePath -> IO (Either Text LocalAgeKey)
parseRemoteAgeKeyStatus :: ByteString -> Either Text RemoteAgeKeyStatus
placeAgeKeyArgs :: TargetProfile -> LocalAgeKey -> Bool -> [String]
```

`LocalAgeKey` intentionally omits the body; inspection reads bytes only long enough to validate and
hash them, while `scripts/iap-ssh.sh send-file` reopens `path` for transport. A fake transport or
small operations record may be introduced for tests, but production must use a `CreateProcess` with
an explicit child environment containing the resolved `NAGARE_CONTEXT`.

`cli/nagarectl/app/Main.hs` adds:

```haskell
data HostCommand
  = HostInit HostInitOpts
  | HostShow (Maybe String)
  | HostPath (Maybe String)
  | HostPlaceAgeKey HostPlaceAgeKeyOpts

data HostPlaceAgeKeyOpts = HostPlaceAgeKeyOpts
  { context :: !(Maybe String)
  , keyFile :: !FilePath
  , force :: !Bool
  }
```

The command line is stable user interface:

```text
nagarectl host place-age-key [--context NAME] --key-file PATH [--force]
```

The transport extension is also explicit:

```text
scripts/iap-ssh.sh send-file <instance> <local-path> -- <remote-command...>
```

It inherits the current `ZONE`, `SSH_USER`, `SSH_KEY`, project guard, OpenSSH options, and bounded
IAP retry policy. Only the new per-attempt file redirection differs from `ssh`.

The NixOS module installs this root-facing interface:

```text
nagare-host-age-key status
nagare-host-age-key install --sha256 <64-lowercase-hex> [--force]
```

Its status protocol is one tab-separated line beginning `age-key`, followed by `ready`, `missing`,
or `invalid`, the configured path, and status-specific fields. Define the exact grammar next to the
parser and test every form. The helper uses Nixpkgs `coreutils` and `systemd`, already present in the
host closure. It calls the sops-nix unit `sops-install-secrets.service` enabled by this plan and the
nixpkgs unit `tailscaled-autoconnect.service`; do not depend on undocumented ad-hoc activation
commands.
