# Nagare 0.22.0

Nagare publishes lifecycle events and delivers them to signed webhooks ([MasterPlan 31](../masterplans/31-publish-durable-nagare-lifecycle-events-and-deliver-webhook-subscriptions.md)), moves a context to a new base domain with its routes, grants and sign-in ([EP-246](../plans/246-move-a-context-to-a-new-base-domain-and-carry-its-routes-grants-and-sign-in.md)), makes the tunnel's edge safe for API clients ([EP-245](../plans/245-make-the-tunnel-s-edge-safe-and-fast-for-api-clients-and-protected-assets.md)), and can sign in native clients and services through the platform's Shōmei ([EP-264](../plans/264-serve-the-platform-shomei-as-an-oidc-provider-for-native-clients.md), [ADR 40](../adr/0040-the-auth-portal-origin-serves-shomei-s-oidc-endpoints-through-the-enforcer.md)).

## Added

- **Lifecycle events** ([EP-231](../plans/231-publish-a-durable-lifecycle-event-feed-with-atomic-source-facts.md)–[EP-233](../plans/233-observe-verified-database-backups-and-publish-lifecycle-events.md)). A context-bound feed of `app.deployed`, `database.backup.completed` and `database.backup.accepted`, each with a stable event ID, committed with the converged release or verified from a backup's signed receipt. `nagarectl events list` and `GET /v1/events` read it. See [Lifecycle events and webhooks](../user/lifecycle-events.md).
- **Webhook subscriptions** ([EP-234](../plans/234-deliver-filtered-webhook-subscriptions-with-durable-retries-and-replay.md)). `nagarectl events webhook create|update|disable|delete` review a subscription; deliveries are signed (HMAC-SHA256, `Nagare-Webhook-Signature`), retried with backoff, recorded, and replayed by review with `events delivery replay`. `events subscription list`, `events delivery list|inspect` and `/v1/events/subscriptions`, `/v1/events/deliveries` inspect them. `cluster/examples/lifecycle-webhook-receiver` is a complete receiver.
- **The lifecycle worker** ([EP-235](../plans/235-run-the-lifecycle-event-service-and-prove-restart-and-upgrade-recovery.md)). `nagarectl context create … --enable-lifecycle-events [--enable-lifecycle-delivery]` runs `nagare-events` as `platform:lifecycle-events`. It reads the inventory and backups, writes only its own state, and may read only the signing Secrets the platform was last planned with. `inventory export` and `restore` carry its state. A cloud context also needs the worker's key ([runbook](../runbooks/lifecycle-worker-key.md)); cloud enablement is not yet proven natively (F154, F155).
- **Move a context to a new base domain** ([EP-246](../plans/246-move-a-context-to-a-new-base-domain-and-carry-its-routes-grants-and-sign-in.md)). `nagarectl context move start|apply|status|rollback` lists what a move changes, carries sites, routes and grants, flips the portal with a passkey export, and retires the old domain once its people have moved. See [Moving to a new base domain](../user/moving-to-a-new-base-domain.md).
- **Sign in native clients and services** ([EP-264](../plans/264-serve-the-platform-shomei-as-an-oidc-provider-for-native-clients.md)). A context that sets `NAGARE_AUTH_ISSUER` serves Shōmei's discovery, JWKS, token and authorization endpoints on the portal host through the enforcer. See [Sign in native clients and services](../user/access.md#sign-in-native-clients-and-services).
- **The tunnel's edge** ([EP-245](../plans/245-make-the-tunnel-s-edge-safe-and-fast-for-api-clients-and-protected-assets.md)). Browser Integrity Check is off and HSTS is sent for six months at the edge; access lines record the visitor address and ray; the connector's metrics are scraped and lost edge connections alert.

## Changed

- ClusterRoles update in place through the Kubernetes adapter.
- A proxied response's `Cache-Control` is tightened instead of replaced.
- Shōmei's, En's, each En tenant's and the Nix cache's databases stay at PostgreSQL 18 (`platformPostgresVersion`) instead of following the payload's default engine version, so a later default cannot plan an in-place major change on every context (F156). Nothing changes today: both are 18.

## Upgrade notes

Nothing changes for the lifecycle worker unless a context opts in; it is off by default. Nothing changes for native sign-in unless a context sets `NAGARE_AUTH_ISSUER`: the packaged manifests are byte-identical, and a context without it plans no auth operation. After adding a database, an app database or a webhook subscription to a context that runs the worker, plan and apply the platform so the worker may read its signing Secret.

## Compatibility and rollback

`transitionsFrom` adds 0.21.0. The admin API image now also carries `nagare-events`. Existing records, journals, reviews and snapshots are unchanged.
