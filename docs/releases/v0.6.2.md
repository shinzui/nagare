# Nagare 0.6.2

Nagare 0.6.2 fixes what the work intranet's upgrade to 0.6.1 had to work around, and makes the
operator's status check fast. It is the first release cut with `just release-candidate` and
`just release-publish`.

This is a pre-1.0 patch release. See [0.6.0](v0.6.0.md) for the in-place upgrade and the
[production-readiness checklist](production-readiness-checklist.md).

## Highlights

- **A converged upgrade plan has no operations (F124).** Every platform stage selects the bootstrap
  stamp, and selecting it planned a check of every Kubernetes and Helm member, so a converged
  transition replanned the same 214 verifications forever and the operator had to judge when to
  stop applying. The planner now checks before the stamp only when the stamp changes, a covered
  scope is unconverged, or a member does not observe as accepted.
- **nagarectl ships its pinned Helm (F123).** The observability release refuses any Helm but
  v4.2.4, and the package carried none, so a transition ran whatever `helm` the operator had. The
  wrapper now puts the pinned Helm first on its PATH, and `nagarectl version --tools` reports it.
- **The release guard runs on every stage.** `inventory apply` ran it only for stages that select
  Pulumi, host or artifact operations, so a stage of only Kubernetes and Helm operations skipped it.
  That is how F122 reached the intranet past the local rehearsal.
- **`inventory status` is about five times faster.** It checks the cluster guard once, reads each
  Kubernetes kind and namespace with one request, and observes independent executors concurrently.
  Against the intranet: 22.7–27.7 s, from 139 s on 0.6.1, with the same 248 findings.
  `inventory store status`, which reads only the store head in seconds, now also reports the open
  transition and the accepted and converged revisions.
- **Auth images follow current En and Shomei.** Nagare pins current upstream revisions, keeps
  Relay relationship queries, handles En's Problem Details responses, and stages every auth image
  from the selected source commits.

## Install

```bash
export NAGARE_VERSION=0.6.2
nix profile install "github:shinzui/nagare/v${NAGARE_VERSION}#nagare"
nagarectl version --json --tools
nagare --list
```

Application developers who do not operate infrastructure may use `#nagarectl` instead.

## Prerequisites

Unchanged from 0.6.1.

## Upgrading

Move a context on 0.4.0, 0.5.0 or 0.6.1 with the 0.6.2 `nagarectl`, as described in
[0.6.0's upgrade steps](v0.6.0.md#upgrading). A converged plan now ends with zero operations, so
stop applying when the plan is empty and commit the transition. A review planned by an earlier
release does not apply with 0.6.2; plan again.

## Compatibility and rollback

`transitionsFrom` adds 0.6.1, the release the intranet runs, and keeps 0.4.0 and 0.5.0. The
supported systems and schema versions are unchanged, `rollbackSupportedFrom` remains empty, and
Nix-by-immutable-tag remains the supported channel.

## Known limitations

As in 0.6.1. F112, F115, F117, F118, F119 and F120 remain deferred (see the
[findings tracker](../audits/mp23-findings.md)).

## Validation

A green full gate and mutation sweep on the candidate, the native output and clone-free rehearsal
of each supported system, and the EP-172 rehearsal record moving a seeded local context from 0.6.1
to this release with the packaged CLIs and every guard. The work intranet's upgrade from 0.6.1
follows publication.
