# Nagare 0.6.6

Nagare 0.6.6 fixes the three defects the work intranet hit while enabling the admin API on 0.6.5.

This is a pre-1.0 patch release. See [0.6.0](v0.6.0.md) for the in-place upgrade and the
[production-readiness checklist](production-readiness-checklist.md).

## Fixed

- **Enabling a new cloud resource applies (F128).** A cloud stage applies each zero-mutation
  update with a targeted `pulumi up --plan`. That run skips resources the program declares but has
  not created, a skipped create's computed outputs are undefined during an update, and Pulumi then
  refused the plan ("dependencies changed"). A saved plan with no mutation now runs no
  `pulumi up`; its convergence preview proves it.
- **The admin API obtains its reader token (F129).** The inventory HTTP manager keeps response
  bodies raw, and gogol's token exchange shares it. Google gzips the token response, so the server
  exited "could not obtain a token". The token response is now decoded. The admin API image must
  be rebuilt from this release.
- **A transition stranded by a close can finish (F130).** A close that keeps a scope at its
  desired revision left it accepted but unconverged, and a converged review recorded only the
  scopes it changed, so `platform transition commit` refused forever. A converged review that
  operated on every managed member of such a scope now proves it. While the store is idle, a
  release that moves the same pinned source supersedes an open transition: its first admitted
  stage retargets the marker. Commit still requires the marker's own payload.

## Install

```bash
export NAGARE_VERSION=0.6.6
nix profile install "github:shinzui/nagare/v${NAGARE_VERSION}#nagare"
nagarectl version --json --tools
nagare --list
```

## Upgrading

Move a context on 0.4.0, 0.5.0, 0.6.1, 0.6.2, 0.6.3, 0.6.4 or 0.6.5 with the 0.6.6 `nagarectl`,
as described in [0.6.0's upgrade steps](v0.6.0.md#upgrading). A context whose 0.6.5 transition is
still open, with no unresolved transaction, is moved by planning the 0.6.6 transition from its
pinned release; the first admitted stage takes the transition over. Enabling the admin API follows
[0.6.5's order](v0.6.5.md#upgrading).

## Compatibility and rollback

`transitionsFrom` adds 0.6.5. Everything else is unchanged from 0.6.5.

## Known limitations

As in 0.6.5. F126 (`context apply` refuses a symlinked context file) and F127 (the kubeconfig
stage refuses a symlinked kubeconfig) remain deferred; see the
[findings tracker](../audits/mp23-findings.md).

## Validation

A green full gate and mutation sweep on the candidate, the native output and clone-free rehearsal
of each supported system, and the EP-172 rehearsal record moving a seeded local context from 0.6.5
to this release. The work intranet's upgrade and its admin API follow publication.
