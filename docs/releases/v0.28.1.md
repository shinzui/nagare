# Nagare 0.28.1

Opting a context into `NAGARE_NIX_CACHE_NAR_SIZE_THRESHOLD`, which 0.28.0 added, failed in two
places on an admitted context. Both are fixed.

## Fixed

- `nagarectl context create NAME --force --nix-cache-nar-size-threshold BYTES --save-plan DIR`
  refused with "context authority or resource identity changed". The threshold is an operational
  input and is now accepted by a reviewed context change.
- A new Attic configuration or image renames the cache's revision-suffixed config-check and
  migration Jobs. Bootstrap let the previous migration Job drop out of the desired inventory, but
  refused the config-check Job it runs after with `retirement-required`. A stateless Job that a
  superseded migration Job is ordered after is now retained with it, without a lifecycle decision.

## Upgrade notes

No config change is needed, and the service images keep their 0.28.0 digests. To opt a context
into whole-NAR storage, review the context change and bootstrap:

```bash
nagarectl context create NAME --force --nix-cache-nar-size-threshold 0 --save-plan DIR
nagarectl context apply DIR --yes
```

## Compatibility and rollback

`transitionsFrom` adds 0.28.0.
