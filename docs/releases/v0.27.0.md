# Nagare 0.27.0

The lifecycle feed now records the changes, failures, backups and upgrades an admin needs to see:
ten new event types, each with its own `data` schema in the admin API's OpenAPI document (EP-276).

## Added

- `change.applied`: every reviewed change that converges, with who applied it, where it came from
  and each scope it created, updated or retired. A deploy has one beside its `app.deployed`; an
  env, secret, access, storage, schedule or CDN change has only this one.
- `change.failed`: the executor recorded that an operation of a change failed or that its outcome is
  unknown; the change waits for a resume or a close. A stop that recorded nothing publishes nothing.
- `change.closed`: a stopped change was closed, its migration abandoned or a proved rollback ended
  it, with each scope reverted or kept.
- `app.deleted`, `app.stopped` and `app.restarted` for applications, standalone services and sites.
- `database.restored`: a reviewed restore converged, into a scratch database or a rebuilt server.
- `database.backup.failed`: a scheduled run failed verification for good (a bad signature, a source
  that is not the recorded incarnation, changed bytes).
- `database.backup.freshness.changed`: a backup schedule moved between `fresh`, `deteriorating` and
  `breached` against its signed recovery-point objective.
- `platform.upgraded`: the context finished moving to a new release.
- The OpenAPI document names one schema per event type (`ChangeAppliedData` and the others), and
  `docs/api/samples/event-types.json` holds one event of each.

## Fixed

- A local context's admin API mounts the lifecycle feed, so `GET /v1/events` serves it instead of
  answering `events_not_enabled`.

## Upgrade notes

No config change is needed. The upgrade publishes new nagare-access and admin API images (En,
Shōmei and the tunnel connector keep their 0.26.0 digests). A context running the lifecycle worker:
the 0.26.0 worker stops at the first event of a new type the move commits, skips nothing, and the
0.27.0 worker publishes from there once it runs, then `platform.upgraded`. Webhook subscriptions name
exact types, so no receiver is sent a new type until an operator adds it. Every converged change now
writes a facts object and a convergence event: a change that had none writes two objects more, a
deploy none. Deployers move to the 0.27.0 CLI and re-plan; a review saved with an older CLI is
refused at apply.

## Compatibility and rollback

`transitionsFrom` adds 0.26.0. The feed head's format is unchanged. The backup collector's state
moves to version 2, which 0.27.0 reads from version 1 and an earlier worker refuses, so a
lifecycle worker is not moved back. Existing journals, reviews, facts and envelopes are unchanged.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the work intranet running the candidate.
