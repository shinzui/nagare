# Nagare 0.18.0

Application workloads declare independent health checks, a worker shutdown allowance and their Kubernetes API access, and the configuration SDK builds natively on ARM64 Linux.

## Added

- **Independent web health checks** ([EP-254](../plans/254-add-independent-application-worker-and-web-health-checks.md)). `WebProbes` holds separate readiness, liveness and startup checks, each with its own path and timings, so readiness can fail without a restart.
- **Worker readiness and a shutdown allowance.** A worker's `readiness` probe is independent of `liveness`, and `shutdown` sets how long it has to drain.
- **Tokenless Pods by default** ([ADR 36](../adr/0036-application-pods-hold-no-kubernetes-api-token-unless-they-name-an-account.md)). Web, worker and task Pods mount no Kubernetes API token unless the workload names a `serviceAccount`. The namespace's `default` account can't be named.
- **Native ARM64 Linux tooling** ([EP-253](../plans/253-package-a-native-arm64-linux-configuration-sdk-and-cli.md)). `packages.aarch64-linux.nagarectl` and the new `nagare-config-sdk` build natively. This is tooling support, not ARM64 production-host support.

## Fixed

- **A deploy using `--hook-affects` can publish and apply its review.** A hook's operation names its Job and the data it affects, and two steps required exactly one resource, so these deploys were refused.
- **A reviewed update can remove a field the first write set.** The create recorded Nagare's fields under an `Update` managed-fields entry that server-side apply doesn't drop, so a removal silently did nothing while the transaction converged. An update now hands that entry to `Apply`, which also repairs existing objects.

## Upgrade notes

This release changes `Config.hs` source:

- Replace `healthCheck`, `HealthCheck` and `httpHealthCheck` with `probes`, `WebProbes` and `httpCheck`. An existing single check becomes `probes = Just (readinessOnly check)`. `expectedStatus`, `asLiveness` and `asStartup` no longer exist on web checks.
- A hand-written `Deployment` literal also sets `serviceAccount = Nothing`, as does a `Task` literal. A `Worker` literal sets `readiness`, `shutdown` and `serviceAccount`.
- A web probe's `checkPort` must be the container port, because Knative rewrites any other.

Every workload's rendered bytes change on its next deploy, and the saved review shows the token setting. A workload that reads the Kubernetes API must name a service account first; create the account and its RBAC yourself.

## Compatibility and rollback

`transitionsFrom` adds 0.17.0. The inventory, journal, review and snapshot formats are unchanged.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the work intranet running the candidate.
