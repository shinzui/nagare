# Nagare 0.16.0

A new context can serve through a Cloudflare Tunnel with no inbound web port. Direct ingress is unchanged for every context that does not
opt in. Moving an existing context is not in this release.

## Added

- **Cloudflare Tunnel for a new context** ([guide](../user/cloudflare-tunnel.md), [ADR 34](../adr/0034-a-context-may-serve-through-one-cloudflare-tunnel-on-a-full-zone.md)).
  `nagarectl context create --ingress cloudflare-tunnel` declares a perimeter with no internet-facing rule beyond IAP SSH and no Cloud DNS, and a
  reviewed `platform:cloudflare-zone` scope: one tunnel, its rules, proxied apex and wildcard records, the edge policy and a cache bypass. The
  connector runs from a release image in the context's own registry, under a restricted profile and a NetworkPolicy.
- **`nagarectl tunnel`.** `token` saves the tunnel token sops-encrypted, `status` compares connectors and rules with what the context declares,
  `rotate` issues a new secret, and `evict` removes a connector.
- **Tunnel checks.** `doctor` reports `Tunnel ingress`, `Tunnel connectors` and `Tunnel rules`. `domains check` and `domains tls` read the edge,
  and report the certificate a visitor gets.
- **Choosing ingress.** `nagarectl init` asks how a context receives traffic, and offers `--ingress`. [A new page](../user/choosing-ingress.md) states what the tunnel
  costs and what you accept. `platform status` and `doctor` print one line on a direct context, silenced by `NAGARE_INGRESS_NOTICE=off`.

## Changed

- **Hostnames in tunnel mode** are one label below the base, `<name>-<namespace>.<base>`, because the free certificate covers one level. Planning
  refuses two workloads on one name, a custom domain outside the zone or deeper than one label, a per-site CDN, and a supplied origin TLS Secret.
- **Protected responses** can carry `Cache-Control: private, no-store, no-transform`, which tunnel mode turns on.

## Fixed

- **A stage stopped by its own payload's defect has an exit** ([F139](../audits/mp23-findings.md)). `inventory close` settles a bootstrap stage
  another payload planned. It writes to no provider, and resume stays refused ([ADR 26 amendment](../adr/0026-stopped-transactions-close-by-per-operation-proof.md)).
- **A rebuilt context reuses its identical artifact** instead of refusing it as `unverified-owner` (F139).
- **A protected site that had a grant can be retired and collected** ([F140](../audits/mp23-findings.md)). A revoked grant's scope now retires at apply, and neither a
  revoked grant nor a release history holds a retired route.
- **A sign-in form survives** a favicon request while it is open (F135), and one left open past its ten-minute CSRF cookie comes back ready to submit instead
  of a bare error.
- **A collected host image build no longer stops an upgrade** ([F141](../audits/mp23-findings.md)). Its output counts as present when the stamped image registered
  from it exists.
- **A Knative Certificate is awaited** like a cert-manager one, so a first bootstrap no longer stops on one read a moment too early.

## Upgrade notes

Nothing changes on a direct context, apart from the one-line notice. The connector image is published only into a context on the tunnel.

## Compatibility and rollback

`transitionsFrom` adds 0.15.0. The inventory, journal, review and snapshot formats are unchanged. `release.json` names a fifth image, `cloudflared`, and a
release that names none stays readable.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the work intranet running the candidate.
