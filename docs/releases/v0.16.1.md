# Nagare 0.16.1

A cloud context can be rebuilt through reviews after losing its VM, and scheduled backups no longer depend on a floating image tag that lost `python3`.

## Added

- **`nagarectl infra forget-lost-vm`.** Pulumi state kept reporting a deleted VM as converged. This drops its record, and refuses unless GCP confirms the VM is gone and the
  refresh changes nothing else. It writes only Pulumi state.
- **`nagarectl kubeconfig plan`.** Reviews the credentials of a cluster rebuilt on a new VM. It is the only way to accept credentials that differ from the accepted ones, and it
  refuses a linked kubeconfig.

## Fixed

- **`inventory rebuild` works on a platform scope** ([F142](../audits/mp23-findings.md)). It refused generated members it had also supplied and retained objects of a retired site. It now
  recreates the cluster scopes its members depend on, such as their namespace.
- **A volume rebuilt `--fresh` runs its scope's migrations again** (F142). They counted as proven, so En crash-looped with no schema. A restored volume keeps its schema and does not.
- **The connector keeps a fresh registry pull token** (F142). Its namespace had no refreshed pull Secret, so once the boot token expired, about an hour after boot, a new connector
  digest could not be pulled.
- **Every GCS Job pins its cloud SDK image by digest** ([F143](../audits/mp23-findings.md)). `google/cloud-sdk:slim` lost `python3` on 2026-11-03, and every scheduled backup needs it, so a
  node pulling the tag fresh took no backup. Accepted schedules are still recognized by their earlier bytes.

## Upgrade notes

The transition moves the platform's own database schedules to the pinned image. Each standalone and app database moves when its own review next runs; until then it depends on the
image cached on the node.

The host configuration changes, so the transition activates the host.

## Compatibility and rollback

`transitionsFrom` adds 0.16.0. The inventory, journal, review and snapshot formats are unchanged.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the work intranet running the candidate.
