# Nagare 0.17.0

A slow site can no longer sign someone out of a long-lived session, and an app database can be restored after losing its server.

## Added

- **Session renewal no longer waits for the site** ([EP-239](../plans/239-deliver-rotated-session-cookies-before-waiting-on-the-upstream.md), IR-41). `nagare-access` spent the refresh token and then waited for the site before sending the replacement, so a request dropped during that wait left the browser with a spent token, and its next renewal ended the session. A GET or HEAD that renews a session now gets an immediate empty `307` to itself carrying the new cookies. Other methods, requests with `Origin` and WebSocket upgrades are still forwarded with the cookies on the response. See [Session renewal](../user/access.md#session-renewal).
- **An app database restores after losing its server** ([F145](../audits/mp23-findings.md), [F150](../audits/mp23-findings.md)). `db app-database escrow-signing-key` and `verify-escrowed-backup` keep its backups verifiable once the cluster is gone, and `db app-database restore-rebuilt` loads one into a server volume a reviewed rebuild created. `inventory rebuild` no longer refuses on a context with an app database.

## Fixed

- **WebSocket handshakes carry renewed cookies.** The enforcer never delivered them on a raw handshake, so an upgrade that renewed a session always lost the new token.
- **ClickHouse restores leave the backups folder writable** ([F151](../audits/mp23-findings.md)). A restore into a server with no backups folder created it as root, and every later backup failed.
- **The builder's idle watchdog counts `ssh-ng` builds and SSH sessions as busy.**

## Upgrade notes

A site needs a change only if it makes a same-origin fetch with `redirect: "error"` or `"manual"`, or rejects `response.redirected`. Such a fetch loses that one request when it happens to renew a session, but not the session. A script with a cookie jar that does not follow redirects now sees the `307` and must store its cookies and repeat the request.

Run `nagarectl db app-database escrow-signing-key` for each app database, and commit the encrypted files. An app database with no escrowed key can't have its backups verified after losing the cluster.

## Compatibility and rollback

`transitionsFrom` adds 0.16.2. The inventory, journal, review and snapshot formats are unchanged.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the work intranet running the candidate.
