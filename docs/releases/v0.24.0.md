# Nagare 0.24.0

`site deploy` prints versioned preview and saved-review documents for deployers ([EP-263](../plans/263-print-versioned-preview-and-saved-review-documents-from-site-deploy.md)). A failed release hook no longer blocks the next application review (BUG-10). The base-domain move ([EP-246](../plans/246-move-a-context-to-a-new-base-domain-and-carry-its-routes-grants-and-sign-in.md)) gets the fixes from its full rehearsal.

## Added

- **Site deploy contract documents** ([EP-263](../plans/263-print-versioned-preview-and-saved-review-documents-from-site-deploy.md)). `site deploy --contract 1` prints a `deploy-preview` document with `--dry-run` and a `saved-review` document with `--save-plan`. A live deploy refuses `--contract`. Every production site deploy, including `site publish`, records the site's configuration digest and its reviewed inputs (`tag`, `imageResource`, `baseDomain`) on the accepted scope. See [the deployer contract](../api/README.md).
- **Retain a member a site no longer declares.** `site deploy --retain-resource RESOURCE-ID --save-plan REVIEW` keeps a dropped route (a removed custom domain) through its own decision. `inventory collect --controller-descendants` then collects it.

## Fixed

- **A failed release hook no longer blocks the next review** (BUG-10). After a failed pre-deploy hook was closed as terminal partial, the next review whose hook declared the same data effect planned the closed hook again. Prepare then refused it with "Kubernetes declared operation must name exactly one bound Job". A hook is now planned only for the review whose scope owns its Job.
- **Event delivery under overlapping workers.** When two workers delivered to one destination, a delivery could go unlogged, and a delivery in flight under a worker that died was never retried. Every eligible delivery in a scanned range is now logged, and a delivery in flight stays pending until it is stale.
- **The base-domain move**, from the EP-246 D8 rehearsal:
  - Every route a redeploy drops is carried until `context move retire`, including the auth portal's old route.
  - Retire makes the old routes deletable and collects them with their controller descendants. It retires the revoked grant scopes, and the admin API's old route goes through a platform review.
  - After a rollback, retire removes the new names' grants and routes.
  - The connector image and component stay declared while the connector's scope is accepted.
  - A protected default host takes its shape from the posture, not the zone.
  - The retained DNS name and the actors are written into the profile.
  - `inventory status` no longer refuses with "reviewed foundation target digest differs from the selected context" after `commit-move`, `retire-dns` or `retire`.
- **Inventory planning:**
  - A member that only gained or lost a dependency keeps its accepted bytes and plans no update. This applies to Kubernetes members, cloud members, template-rendered members and the bootstrap stamp.
  - An unchanged accepted Helm release plans with its accepted contract.
  - A DomainMapping updates in place.
  - The finalizer k3s ServiceLB adds to a Service is accepted as the controller's.
  - A public tunnel Service's stored bytes rebind their flattened claim.

## Changed

- The default static site base is `nginx:1.30.7-alpine` (was `nginx:1.27-alpine`). A site image built from the default base changes digest on its next build.

## Upgrade notes

The first site deploy after the upgrade records a new scope revision for the digest and inputs, with no member change. No config change is needed.

## Compatibility and rollback

`transitionsFrom` adds 0.23.0. Existing records, journals, reviews and snapshots are unchanged.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the work intranet running the candidate.
