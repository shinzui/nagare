# Nagare 0.19.2

The first foundation apply after a delegation now succeeds, and a revoked delegation no longer wedges the next platform transition. Both were findings of the [native IAM check](../audits/ep248-cloud-iam-check-2026-11-11.md) of [EP-248](../plans/248-issue-least-privilege-credentials-to-a-delegated-deployer.md).

## Fixed

- **A delegated deployer's inventory store grant binds predefined roles.** It bound a custom role created in the same Pulumi update, and IAM had not yet propagated that role, so the first foundation apply after a delegation failed until the operator closed the transaction and planned again. The grant now binds Storage Object User and Storage Bucket Viewer under the same prefix condition. Object User also allows update, restore and move, still only beneath the context's inventory prefix. Nothing needs a custom role ID any more, which a deleted role held for about 37 days.
- **A platform transition converges a drifted cloud foundation first.** A delegation created or revoked, or a context edit, with no bootstrap since, used to stop the transition's cloud stage after earlier stages had applied, and neither release's CLI could go on. The transition now plans that foundation stage first, as bootstrap does.

## Upgrade notes

A cloud context with a delegation replaces its custom store role with the two predefined bindings on its next foundation stage. Contexts without delegations are unchanged.

## Compatibility and rollback

`transitionsFrom` adds 0.19.1. The inventory, journal, review and snapshot formats are unchanged.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the work intranet running the candidate.
