# Nagare 0.19.1

A delegated deployer works on a cloud context. In 0.19.0, its credentials could not be issued from a clean shell, and with credentials issued by hand it still could not open the context's inventory store. These faults were found by the [native IAM check](../audits/ep248-cloud-iam-check-2026-11-11.md) of [EP-248](../plans/248-issue-least-privilege-credentials-to-a-delegated-deployer.md).

## Fixed

- **`delegation credentials` selects the context's Pulumi stack before its project guard.** From a clean environment it read Pulumi's default backend and refused with "no stack named".
- **A cloud deployer's bundle activates its key in its own gcloud configuration.** gcloud's credential helper, which the store's session reads, crashed on the key file override that 0.19.0 set.
- **A deployer's store requests name no quota project.** Naming one needs `serviceusage.services.use` on the project, which the deployer does not hold, so its first read was refused. An operator's requests are unchanged.

## Upgrade notes

A bundle issued by 0.19.0 on a cloud context does not work. Run `nagarectl delegation credentials NAME --out DIR` again with 0.19.1, which also rotates the key. Local contexts are unaffected.

After `delegation revoke` on a cloud context, run `platform bootstrap plan` and apply it before the next platform transition. That reconverged foundation is what disables the deployer's cloud account. A transition started before it stops at the foundation stage.

## Compatibility and rollback

`transitionsFrom` adds 0.19.0. The inventory, journal, review and snapshot formats are unchanged.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the work intranet running the candidate.
