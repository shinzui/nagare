# Nagare 0.14.0

Nagare 0.14.0 reports what a context has installed and runs: the Nagare release beside the build
serving the admin API, the host's NixOS identity, every platform component's declared and running
images, and every managed database server's declared and reported engine version.

## Added

- **`GET /v1/platform/versions`** on the admin API. One `platform-versions` document with the
  installed release from the cluster stamp beside the serving build and a `match`, `different` or
  `unknown` comparison; nodes with their OS image, kernel and k3s versions and the host's recorded
  NixOS release, code name and nixpkgs revision; each accepted platform component's declared
  version, chart and images beside its pods' image digests; and each PostgreSQL, ClickHouse and
  Redis server's declared version beside the version it reports. Every value carries its source,
  read time and, when missing, a reason; an unreadable source leaves the rest of the document
  served. The route keeps the API's ETag and 304 contract (EP-236).
- **`nagarectl platform versions [--json] [--contract 1]`** prints the same document from the
  store, and **`nagarectl platform versions refresh`** collects and publishes the snapshot the API
  serves within 60 seconds. A converged `inventory apply` or `platform bootstrap apply` that
  changed a `platform:` or `database:` scope refreshes it for up to 20 seconds and prints one
  `versions:` line on stderr; a failure there never changes the apply's outcome (EP-236).
- **Host identity recorded at activation.** The host module writes the
  `kube-system/nagare-host-identity` ConfigMap with the evaluated NixOS release, code name, version
  and nixpkgs revision. A host reports `not_recorded` until its next `just host-switch`.

## Changed

- **The admin API reader may read `versions/latest.json`.** Its exact object grant gains that one
  name; native payloads, reviews, journals, listing and writes stay refused, and every snapshot
  read rechecks the bucket's owner.
- **`inventory status` reads its health checks concurrently.**

## Compatibility and rollback

`transitionsFrom` adds 0.13.0. The inventory, journal and review formats are unchanged; the
snapshot is a derived object outside the inventory's listings, exports and migrations, and the new
document is an addition to contract version 1.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the
work intranet running the candidate.
