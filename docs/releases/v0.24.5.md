# Nagare 0.24.5

WebSocket connections reach protected sites.

## Fixed

- **A WebSocket to a protected host reaches nagare-access.** Every WebSocket upgrade to a `requireLogin` host failed at Kourier with 503 UC, so a browser saw close code 1006. Knative names a route's placeholder port `http2`, so Kourier made the DomainMapping's hop back into its internal listener HTTP/2, and Envoy cannot forward an upgrade over that hop (net-kourier #801). A DomainMapping whose target is the nagare-access enforcer now carries `kourier.knative.dev/disable-http2: "true"`, which makes that hop HTTP/1.1. nagare-access proxies over HTTP/1.1 anyway. Routes to a site's own service keep Kourier's default. Reported from `mori://shinzui/kotei-ui`: the console's run socket on its protected host never connected.
- **The route check sends a WebSocket upgrade.** `nagare-harness route-check` now sends an anonymous HTTP/1.1 WebSocket upgrade to the protected host and fails unless the enforcer answers 302 or 401.

## Upgrade notes

No config change is needed. The admin API route moves with the platform transition. A protected site's route lives in the site's own scope, and Kourier gives every route to nagare-access one shared Envoy cluster, so WebSockets work only once every protected route carries the annotation: redeploy every protected site with the 0.24.5 CLI. Deployers move to the 0.24.5 CLI and re-plan; a review saved with an older CLI is refused at apply.

## Compatibility and rollback

`transitionsFrom` adds 0.24.4. Existing records, journals, reviews and snapshots are unchanged.

## Validation
