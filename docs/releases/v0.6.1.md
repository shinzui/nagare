# Nagare 0.6.1

Nagare 0.6.1 fixes the two defects that stopped the work intranet's first in-place upgrade on
0.6.0. Both refused or misrouted the upgrade before any change reached the intranet.

This is a pre-1.0 patch release. See [0.6.0](v0.6.0.md) for the in-place upgrade it completes and
the [production-readiness checklist](production-readiness-checklist.md).

## Highlights

- **A cloud context's transition stages apply (F122).** 0.6.0's `inventory apply` ran the ordinary
  release guard on every cloud stage. That guard refuses minor skew, which is the state a
  transition exists to close, so no cloud context could leave 0.5.0. A review with a transition
  identity, already bound to the payload that planned it and the context pin it expects, now
  refuses only a major mismatch. The local rehearsal skips that guard, so it did not catch this.
- **The host builds on the context's builder (F121).** The host stage built its NixOS closure with
  a plain `nix build`, so it used the operator machine's default builders, possibly in another
  project, and sent the host flake (with its encrypted secrets) there. It now builds on the
  context's builder (`NAGARE_BUILDER_PROJECT`, `NAGARE_BUILDER_ZONE`, `NAGARE_BUILDER_INSTANCE`)
  through the pinned IAP tunnel the host image build already used. It refuses a builder in another
  project, and a Nix daemon that does not trust the operator, since that daemon would ignore the
  context builder.

## Install

```bash
export NAGARE_VERSION=0.6.1
nix profile install "github:shinzui/nagare/v${NAGARE_VERSION}#nagare"
nagarectl version --json --tools
nagare --list
```

Application developers who do not operate infrastructure may use `#nagarectl` instead.

## Prerequisites

Unchanged from 0.6.0. The host stage now requires the context's builder to be in the context's
project and the operator to be a trusted user of the local Nix daemon.

## Upgrading

Move a context on 0.4.0 or 0.5.0 with the 0.6.1 `nagarectl`, as described in
[0.6.0's upgrade steps](v0.6.0.md#upgrading). A review planned by 0.6.0 does not apply with 0.6.1;
plan again. No context is known to run 0.6.0, and `transitionsFrom` does not list it.

## Compatibility and rollback

Unchanged from 0.6.0: `transitionsFrom` lists 0.4.0 and 0.5.0, the supported systems and schema
versions are the same, `rollbackSupportedFrom` remains empty, and Nix-by-immutable-tag remains the
supported channel.

## Known limitations

As in 0.6.0. F112, F115, F117, F118, F119 and F120 remain deferred (see the
[findings tracker](../audits/mp23-findings.md)).

## Validation

A green full gate on the candidate, the native output and clone-free rehearsal of each supported
system, the EP-172 rehearsal record moving a seeded local context from 0.5.0 to this release, and
the work intranet's upgrade from 0.5.0 to this commit before the tag.
