# Nagare 0.23.0

An Application can declare a migration hook that runs only as a reviewed release prerequisite, never on a schedule ([EP-269](../plans/269-declare-release-only-migration-hooks-that-no-schedule-can-run.md), IR-46).

## Added

- **Release-only pre-deploy hooks** ([EP-269](../plans/269-declare-release-only-migration-hooks-that-no-schedule-can-run.md)). A `Task` in an `Application`'s `tasks` list may declare `trigger = ReleaseOnly`, or be built with `releaseHook`. `app deploy` runs it as the pre-deploy Job before the Service and workers, exactly as before, and accepts its CronJob with `suspend: true` on the schedule `0 0 31 2 *`, which never fires. The preview and the saved review show `hookTrigger/TASK: release-only` under the application scope's overrides. Changing an accepted scheduled hook to release-only under the same tag updates only its CronJob, in place; the hook is not run again. `task list` prints such a task's schedule as `suspended`. See [Release-only tasks](../user/scheduled-tasks.md#release-only-tasks).

## Changed

- A release-only task anywhere but an `Application`'s `tasks` list (on a Service, or a standalone task config) is refused at load.

## Upgrade notes

**Breaking for configs that build a `Task` record:** the `schedule` field is now `trigger`. Replace `schedule = s` with `trigger = OnSchedule s` (and import `TaskTrigger (..)` from `Nagare.Dsl.Task`). A config that uses the `scheduledTask` preset needs no change. A scheduled task's rendered config and CronJob bytes are unchanged, so no accepted application changes until its config does. A migration hook can switch to `trigger = ReleaseOnly` with an ordinary reviewed `app deploy`. Changing a release-only task back to a schedule with no `startingDeadlineSeconds` may start a run it counts as missed at once.

## Compatibility and rollback

`transitionsFrom` adds 0.22.0. Existing records, journals, reviews and snapshots are unchanged.
