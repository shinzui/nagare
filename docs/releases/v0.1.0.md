# Nagare 0.1.0

Nagare 0.1.0 is the first Nix-distributed release. It packages the typed `nagarectl`
runtime and the immutable platform assets needed for local and GCP operation, so an operator can pin
and run Nagare without a source checkout.

## Highlights

- Run the CLI or operator recipes from the immutable `v0.1.0` flake reference.
- Keep cloud and local targets isolated in named contexts under XDG configuration and state roots.
- Generate context-owned NixOS host flakes with explicit SSH keys and encrypted secret references.
- Inspect CLI, payload, context, host, and cluster versions before mutation.
- Plan, apply, resume, and explicitly roll back a staged per-context platform upgrade.

## Install

After the maintainer publishes the tag, inspect the CLI without cloning:

```bash
nix run github:shinzui/nagare/v0.1.0#nagarectl -- version --json
```

For a persistent profile installation:

```bash
nix profile install github:shinzui/nagare/v0.1.0#nagarectl
```

## Compatibility and limits

The supported client systems are `x86_64-linux` and `aarch64-darwin`. Nix is the only supported
distribution channel in this release; there are no portable binary archives, Homebrew formulae, or
CLI container images. Cloud provisioning still requires the operator's GCP authentication, and local
operation requires Docker. Operator recipes also expect the third-party clients listed in Getting
Started, including Pulumi, Node, gcloud, kubectl, Helm, sops, age, and Tailscale as applicable; the
release packages Nagare's commands and payload, not those tools. Publishing a release never selects
or upgrades a live context.

All capabilities remain experimental in 0.1.0. This initial release has no earlier Nagare release to
upgrade or automatically roll back from, so `rollbackSupportedFrom` is empty. Release selection does
not restore databases, persistent volumes, or Pulumi state.

The optional Shomei/En authentication plane is built from local source checkouts. Set `SHOMEI_SRC`
and `EN_SRC` when those repositories are not at the documented defaults; a fresh private-dependency
build also needs appropriate GitHub read access. The locally validated auth migration path recreates
Nagare's unused pre-0.2 Shomei database because that dependency rewrote historical checksums; do not
apply that discard procedure to a deployment with retained auth data.

Preserve an existing context's prior payload and run `nagarectl platform status` before changing its
pinned version.
