# Nagare 0.20.0

An app can own its PostgreSQL app database and manage its own roles and privileges with its own SQL. Nagare keeps apps apart on the shared server ([IR-43](../improvement-requests/let-an-app-own-its-database.md), [MasterPlan 35](../masterplans/35-let-an-app-own-its-database-on-a-shared-postgresql-server.md), [ADR 37](../adr/0037-an-app-may-own-its-database-and-nagare-keeps-apps-apart.md)). Tasks and pre-deploy hooks bind app databases, and any binding can name its URL variable.

## Added

- **App-owned app databases** ([EP-257](../plans/257-declare-an-app-owned-postgresql-app-database-and-keep-apps-apart.md)). `ownership = AppOwned {databaseOwner = …}` gives the app one owner login, `<name>_owner` with Secret `<name>-owner`, with `CREATEROLE` and nothing else server-wide. The app's own SQL creates its roles and logins, memberships, ownership changes and grants, and none of it is drift. Planning refuses anything that reaches another app's roles or database, Nagare's users, or a server-wide attribute or predefined role, naming the role. PostgreSQL 18 or later.
- **The app's roles go through backups and maintenance** ([EP-258](../plans/258-carry-an-app-s-roles-through-backups-restores-quiesce-and-retirement.md)). An app-owned backup is one `tar.gz` holding the dump and a role file with the app's roles, logins, password verifiers, memberships and database grants. Restore, scratch or `--rebuilt`, recreates them before the data and refuses a role file that reaches outside the app. Quiesce and retirement close the logins the app created, and resume reopens exactly those.
- **Tasks and hooks bind app databases** ([EP-259](../plans/259-let-tasks-and-pre-deploy-hooks-bind-an-app-database-under-a-named-url-variable.md)). `Task` has `appDatabases`, and every binding is an `AppDatabaseBinding` with an optional `urlVariable`. A task named in an app database's `owners` gets the migration credential, or the owner credential of an app-owned database, and the Application's web and worker Pods never reference it.

## Fixed

- **A reviewed rebuild of an app database that was ever quiesced is planned.** A fresh rebuild re-ran the drain and resume a quiesce leaves declared, and the drain refused with "an app-database drain or resume covers no user". Those two now keep their proof, and migrations and hooks still run again on the empty volume.
- **A Pulumi apply waits for a new custom role to propagate.** A binding to a custom role created earlier in the same update ("Role … does not exist in the resource's hierarchy") is retried with the same saved plan, up to four times 30 seconds apart. A context enabling the admin API reader for the first time no longer stops once.

## Upgrade notes

This release changes `Config.hs` source:

- An `AppDatabase` literal sets `ownership`. Use `ownership = NagareManaged` to keep the runtime and migration users.
- A `Deployment` or `Worker` lists `appDatabases` as bindings: `appDatabases = map appDatabaseBinding [pg, ch]` keeps today's fixed variables.
- A `Task` literal sets `appDatabases = []`, or the bindings it uses.

An app-owned app database is a new app database, because ownership is fixed at creation. Existing app databases, their backups and their restores are unchanged.

## Compatibility and rollback

`transitionsFrom` adds 0.19.2. The inventory gains an app-owned database member kind and the `tar.gz` backup format. Existing records, journals, reviews and snapshots are unchanged.
