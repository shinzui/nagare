# Nagare 0.24.1

A revoked delegation that named a repository it could never have a cloud principal for no longer blocks `platform bootstrap plan` (FRIC-82, `mori://shinzui/kotei/okf/friction-log/concepts/FRIC-82`).

## Fixed

- **A revoked principal-less delegation no longer blocks bootstrap.** A delegation accepted with an image repository that cannot have a cloud principal (the platform's shared Artifact Registry repository, another project or region, or not an Artifact Registry ID) and then revoked was still put in the derived `nagare:delegatedDeployers` config. Every later `platform bootstrap plan`, and the foundation stage of a transition, refused with "cannot have a cloud principal". Such a delegation never had a service account, so it is now left out. A revoked delegation with a valid repository still keeps its principal with the account disabled, and an active one with a refused repository still refuses.
- **`delegation create` refuses that repository at planning.** On a cloud context, a delegation the next bootstrap could not give a cloud principal is refused before it is accepted. This covers the shared repository, another project or region, a name that is not an Artifact Registry repository ID, and a repository another delegation's principal already has. The refusal no longer waits for `delegation credentials` or the next bootstrap.
- **A closed transaction no longer blocks the next plan on its release images.** When `inventory close` leaves an artifact scope unconverged, the next plan verifies its unchanged artifacts. The artifact executor refused that verification ("only executes reviewed creation, update, or publication operations"), so every later plan stopped. It now verifies by observing the registry: it completes when the accepted digest is present, and it never publishes.

## Upgrade notes

No config change is needed. On a context that holds such a revoked delegation, the next `platform bootstrap plan` declares only the remaining delegations' principals.

## Compatibility and rollback

`transitionsFrom` adds 0.24.0. Existing records, journals, reviews and snapshots are unchanged.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the work intranet running the candidate.
