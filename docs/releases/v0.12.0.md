# Nagare 0.12.0

Nagare 0.12.0 makes a platform transition cost what changed. A release whose deployment meaning
is unchanged keeps every accepted scope, moves only its stamp, and proves the stamp's members from
grouped reads instead of journaling a verification per member; independent workload updates wait
for readiness together; and the transition commit survives a stop between the context pin and the
store (MasterPlan 30).

## Changed

- **A release compiled from another workspace keeps its scope revisions.** Scopes are compared by
  deployment meaning, not by the path they were compiled from; only the stamp moves (ADR 22,
  EP-225).
- **Unchanged members are proved at admission, not journaled.** The 205 per-member verifications
  of an intranet platform stage are validations proved from one fresh grouped read before the
  transaction starts; a drifted, deleted or replaced member still refuses (EP-225, EP-227).
- **A command guards its cluster once.** Every Kubernetes, Helm and access request then uses a
  private kubeconfig flattened from the guarded context; a changed kubeconfig, a replaced server
  node or a host activation re-admits or refuses (ADR 18, EP-226).
- **Plans read in grouped batches.** A platform stage's planning read fell from about 880 kubectl
  processes to about 70 in the local rehearsal (EP-226).
- **Up to four independent stateless updates await readiness together.** Journal writes stay
  serialized; dependent, stateful, data and host work stays one at a time. Stateless readiness is
  bounded at 180 s, and overlapped waits print progress every five seconds (EP-228).
- **Each transition plan prints its impact**, and the release runner stops a loop that repeats
  its work (EP-228).

## Fixed

- **`platform transition commit` no longer pins over unfinished work.** It judges the store again
  under the lock, records its intent in the transition marker, writes the pin, then closes the
  marker; a stop at any point is finished by committing again (ADR 6, EP-228).

## Compatibility and rollback

`transitionsFrom` adds 0.11.1. A review with validations is refused by 0.11.1's decoder, and
while a commit is finalizing, older CLIs refuse the head; neither changes data. The journal and
the rest of the inventory format are unchanged.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the
work intranet running the candidate.
