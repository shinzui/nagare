# Nagare 0.26.0

Upgrading a context now brings every accepted login-protected route up to the WebSocket fix of
0.24.5, and a reviewed field takeover no longer leaves a field owned by two writers.

## Changed

- Once the platform scopes have no work left, the upgrade's last stage re-declares every accepted
  route to nagare-access that was rendered before v0.24.5 and so lacks
  `kourier.knative.dev/disable-http2`. Kourier builds one Envoy cluster for all of those routes, so a
  single one without the annotation can fail every WebSocket upgrade to every `requireLogin` host.
  The stage adds the annotation to the route's accepted bytes and changes nothing else: no site
  config is compiled, and the route keeps its identity and its grants. It covers site and platform
  scopes, and `platform transition commit` refuses while such a route is left (EP-273).
- A route annotated by hand with `kubectl annotate` is listed in the stage's review as a field
  takeover from `kubectl-annotate`; applying it makes the annotation Nagare's.
- After a `--take-over-fields` apply, Nagare removes the fields its own apply owns from each reviewed
  writer's managed-field entry, by a patch bound to the object's UID and resourceVersion that changes
  no field. Before, a field the other writer had already set to the declared value stayed owned by
  both, the takeover stopped ambiguous and every later update of the object refused. A field Nagare
  does not declare stays with its writer and still refuses.

## Upgrade notes

No config change is needed. Upgrading from 0.25.2 plans no host activation and publishes no image
(every release image keeps its 0.25.2 digest); it updates the
DomainMapping of each accepted protected route that lacks the annotation, and nothing else in the
cluster. Deployers move to the 0.26.0 CLI and re-plan; a review saved with an older CLI is refused at
apply.

## Compatibility and rollback

`transitionsFrom` adds 0.25.2. Existing records, journals, reviews and snapshots are unchanged.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the work intranet running the candidate.
