# Nagare 0.11.1

Nagare 0.11.1 makes a reviewed access change faster: a team-membership plan takes about 3 s
instead of about 6 s, and an apply after a platform transition no longer downloads the whole
inventory journal again.

## Fixed

- **An apply downloads only the journal events it lacks, however many there are.** With a valid
  cached prefix, more than 64 new events (normal after a platform transition) made every command
  read the whole journal again; one apply took 112 s. The anchor and exactly the missing events
  are now read at every tail length (ADR 22, EP-217).

## Changed

- **Opening the inventory checks bucket and project ownership at the same time.** Both answers
  must still arrive and agree before anything is read or written.
- **Access plans and `access check` prepare their en connection while the inventory opens.** The
  cluster guard still passes before the port-forward opens, nothing opens without the private
  key, and no request is sent early.
- **`NAGARE_TRACE=1` attributes a command's time and transfers.** It names the gcloud credential
  helper, ownership reads, en forward, cluster guard, en requests and owner reads, and counts the
  actual metadata, media, listing and upload requests and bytes by object class.

## Compatibility and rollback

`transitionsFrom` adds 0.11.0. The inventory format and every reviewed operation are unchanged.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the
work intranet running the candidate.
