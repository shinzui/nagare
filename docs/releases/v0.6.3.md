# Nagare 0.6.3

Nagare 0.6.3 protects static and server sites behind login, grants sites to teams, and fixes what
the first static-site deployment to the work intranet ran into: redirects that exposed the
container port, text without a UTF-8 charset, an access review that failed late without its API key,
and a failed certificate with no diagnosis.

This is a pre-1.0 patch release. See [0.6.0](v0.6.0.md) for the in-place upgrade and the
[production-readiness checklist](production-readiness-checklist.md).

## Highlights

- **Protected static and server sites (EP-186).** `StaticSite` and `ServerSite` take the same
  `access` field as an application and route through the shared enforcer. A preview of a protected
  site is its own protected hostname with its own backend entry. The gateway asks En at a fully
  consistent snapshot on every decision-cache miss, so a revoked grant stops a session within the
  decision TTL. The planner refuses to turn an accepted public route protected in place; retire it
  through a reviewed plan first. See [access](../user/access.md).
- **Team grants (EP-187).** `nagarectl access team add-member|remove-member|list-members` and
  `nagarectl access grant|revoke --host HOST --team TEAM` are always reviewed. Listing reads stored
  relationships at a fully consistent snapshot and refuses to print a partial list.
- **Effective-access check (EP-188).** `nagarectl access check --host HOST --user EMAIL [--json]`
  reports allowed, denied, conditional or unavailable for one user on one protected host. It
  writes nothing.
- **Certificate diagnosis and renewal (IR-28).** `nagarectl domains tls HOST [--json]` walks
  DomainMapping, Knative and cert-manager Certificates, the latest CertificateRequest, the ACME
  Order and Challenges, and classifies the chain as ready, issuing, failed, rate-limited or
  incomplete. It never reads Secrets. `--renew --yes` retries a failed certificate this context owns
  with one resourceVersion-tested status patch, and refuses wildcards and every other verdict. A
  deploy that stops on TLS prints the verdict and the command.
- **Static-site redirects and charset (BUG-5, BUG-6).** The generated Nginx configuration now
  issues relative redirects instead of `http://<host>:8080/…`, and serves text as `charset=utf-8`.
  Existing sites pick this up on their next `nagarectl site deploy`.
- **Missing access key refuses before admission (IR-27).** `inventory apply` and `inventory resume`
  refuse a review with access operations when `NAGARE_EN_API_KEY` is unset or empty, before
  anything is admitted, and the saved review stays valid.

## Install

```bash
export NAGARE_VERSION=0.6.3
nix profile install "github:shinzui/nagare/v${NAGARE_VERSION}#nagare"
nagarectl version --json --tools
nagare --list
```

Application developers who do not operate infrastructure may use `#nagarectl` instead.

## Prerequisites

Unchanged from 0.6.2.

## Upgrading

Move a context on 0.4.0, 0.5.0, 0.6.1 or 0.6.2 with the 0.6.3 `nagarectl`, as described in
[0.6.0's upgrade steps](v0.6.0.md#upgrading). The bootstrap En schema gains group membership and
widens app viewers to team members. The change is additive: existing user grants keep working. The
`en` Deployment carries the schema digest, so the transition rolls the `en` server once. A review
planned by an earlier release does not apply with 0.6.3; plan again.

## Compatibility and rollback

`transitionsFrom` adds 0.6.2, the release the intranet runs, and keeps 0.4.0, 0.5.0 and 0.6.1. The
supported systems and schema versions are unchanged, `rollbackSupportedFrom` remains empty, and
Nix-by-immutable-tag remains the supported channel.

## Known limitations

As in 0.6.2. F112, F115, F117, F118, F119 and F120 remain deferred (see the
[findings tracker](../audits/mp23-findings.md)).

## Validation

A green full gate and mutation sweep on the candidate, the native output and clone-free rehearsal
of each supported system, and the EP-172 rehearsal record moving a seeded local context from 0.6.2
to this release with the packaged CLIs and every guard. The site-access drill proved protected
sites and team grants on a disposable local context, and the EP-191 drill proved certificate
renewal. The work intranet's upgrade from 0.6.2 follows publication.
