# Nagare 0.2.2

Nagare 0.2.2 restores clone-free onboarding for a new cloud cluster. It fixes host configuration
generation, prevents a new named context from inheriting another context's project-owned names, and
ships the Pulumi runtime used by the operator package. Nagare 0.2.0 and 0.2.1 cannot generate a
valid new host flake; use 0.2.2 for new platform onboarding.

## Changes

- **Valid generated host modules (IR-13).** `nagarectl host init` once again writes the declared
  `nagare.host.hostName` option. The generated `host.nix` agrees with the NixOS module and evaluates
  instead of failing on an unknown `nagare.host.name` option.
- **Isolated named initialization (IR-7).** `nagarectl init NAME` now builds a new context only from
  its flags, built-in defaults, and, with `--force`, `NAME`'s own stored context. It does not read the
  active context or ambient target variables. Before a write or cloud call it prints the project,
  registry prefix, buckets, instance, and Pulumi backend, and refuses stored bucket names that do not
  belong to the selected project. A forced re-initialization keeps omitted Pulumi backend fields
  instead of resetting a GCS context to `local`.
- **Operator Pulumi and early tool checks (IR-8).** The full `nagare` package includes Pulumi and
  `pulumi-language-nodejs` from the release's pinned nixpkgs. An operator-provided Pulumi earlier on
  `PATH` still wins. `init` checks for every tool required by its enabled phases before prompting or
  changing files, and a missing Pulumi is a normal diagnostic rather than an uncaught process error.
- **Recoverable initialization.** Failures after the context is written identify a retry through
  `nagarectl context use NAME` or a safe `nagarectl init NAME --force` invocation. Installed-payload
  next steps use `nagare <recipe>`, and `nagare --list` no longer initializes Pulumi state or requires
  npm merely to inspect recipes.
- **Tool visibility.** `nagarectl version --tools` reports the `pulumi`,
  `pulumi-language-nodejs`, `gcloud`, and `npm` executables selected from `PATH`; combine it with
  `--json` for machine-readable diagnostics.

## Install

Install the full operator package for platform onboarding:

```bash
nix profile install github:shinzui/nagare/v0.2.2#nagare
nagarectl version --json --tools
nagare --list
```

Node.js with npm and the Google Cloud SDK remain separate workstation prerequisites. The smaller
`#nagarectl` output remains available for app developers and intentionally does not carry Pulumi.

## Upgrading

Changing the workstation package does not change any Nagare context, host, cluster, or Pulumi state.
Existing 0.2.1 contexts require no schema migration for this patch release. Install 0.2.2, inspect
`nagarectl platform status`, and use the staged [per-context upgrade](../user/upgrades.md) only when
you deliberately want to advance a context's release pin and payload.

For an existing context, `init NAME --force` now preserves omitted fields from that same context.
Review the printed derived-name summary before allowing initialization to continue; a foreign bucket
refusal should be corrected in the context rather than bypassed.

## Compatibility and rollback

- **Systems and schemas.** Supported client systems remain `x86_64-linux` and `aarch64-darwin`.
  Asset, host-flake metadata, and compatibility schema versions remain 1.
- **State and migrations.** This release changes workstation packaging and initialization behavior.
  It has no Pulumi resource-schema, NixOS state-version, Kubernetes, database, or persistent-data
  migration.
- **Rollback.** `rollbackSupportedFrom` remains empty. Selecting another workstation package never
  restores infrastructure, databases, persistent volumes, or Pulumi state.
- **Experimental.** All capabilities remain experimental.

## Known issues

- IR-9 remains open: `nagarectl context guard` can misreport some Pulumi startup or backend failures
  as a missing `gcp:project` value.
- IR-14 remains open: the default host name can collide when multiple Nagare hosts share one
  tailnet.
- `nixos/flake.nix` checks are not part of the root CI flake checks. The release retains the focused
  generated-option agreement check instead of claiming full generated-host evaluation in CI.

## Validation gaps

The release gates cover 462 Haskell tests; strict Haskell style and user-documentation validation;
the generated-host option agreement; a hermetic foreign-current-context initialization scenario;
missing-tool refusal before gcloud or context writes; and an installed-package-only `PATH` that
finds and starts the bundled Pulumi and Node.js language plugin. The clone-free and full flake checks
run natively on both declared systems in the Release workflow.

No live GCP project was mutated while preparing this release. The GCS bucket bootstrap, real API
enablement, and a complete new-cluster Pulumi apply remain operator-run steps protected by the
existing context and replacement guards.
