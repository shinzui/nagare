# Nagare 0.24.2

Pods in every namespace, delegated ones included, pull the context's private Artifact Registry images.

## Fixed

- **Delegated namespaces can pull private images.** The host refreshed a registry pull Secret only in `personal`, `nagare-system`, `cloudflare-tunnel` and `knative-serving`, so a delegation's build Job (in `kotei-ci-builds`, for example) failed with `ErrImagePull` and `401 Unauthorized`. Kubernetes 1.35 re-checks a pod's own credentials before it reuses a pulled image, so pre-pulling did not help. The host now runs a kubelet image credential provider. It answers each pull of the registry host with the VM's metadata token, so any namespace pulls with no pull Secret, and the token never lands in an object a tenant can read. Pull access is project-wide, as the pull Secret's was.

## Upgrade notes

The host transition restarts k3s with the credential provider. No config change is needed. The existing pull Secrets stay and keep refreshing.

## Compatibility and rollback

`transitionsFrom` adds 0.24.1. Existing records, journals, reviews and snapshots are unchanged.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the work intranet running the candidate.
