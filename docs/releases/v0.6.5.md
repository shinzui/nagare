# Nagare 0.6.5

Nagare 0.6.5 fixes the one defect that kept an installed cloud context from enabling the admin
API introduced in [0.6.4](v0.6.4.md).

This is a pre-1.0 patch release. See [0.6.0](v0.6.0.md) for the in-place upgrade and the
[production-readiness checklist](production-readiness-checklist.md).

## Fixed

- **An installed cloud context can enable the admin API (F125).** The reader account's six creates
  plan as one grouped operation. In 0.6.4 their catalog layers interleaved with the existing
  firewalls and subnet. Those re-plan as zero-mutation updates when the catalog changes, so
  admission refused the review with an operation dependency cycle before applying anything. The
  reader is now ordered after every other cloud layer, and the Pulumi parity test requires that.

## Install

```bash
export NAGARE_VERSION=0.6.5
nix profile install "github:shinzui/nagare/v${NAGARE_VERSION}#nagare"
nagarectl version --json --tools
nagare --list
```

## Upgrading

Move a context on 0.4.0, 0.5.0, 0.6.1, 0.6.2, 0.6.3 or 0.6.4 with the 0.6.5 `nagarectl`, as described in
[0.6.0's upgrade steps](v0.6.0.md#upgrading). Enable the admin API only once the context is pinned
to the release: the cloud foundation, which carries the reader's Pulumi configuration, plans only
for a context whose pin matches its payload. The order is:
1. the transition, then `transition commit`;
2. `NAGARE_ADMIN_API_ENABLED=1`;
3. `platform bootstrap plan` and apply for the foundation configuration, then for the reader
   account;
4. the reader key ([admin API reader](../runbooks/admin-api-reader.md));
5. `platform bootstrap plan` and apply for the `admin-api` scope.

## Compatibility and rollback

`transitionsFrom` adds 0.6.4. Everything else is unchanged from 0.6.4.

## Known limitations

As in 0.6.4. F126 (`context apply` refuses a symlinked context file) and F127 (the kubeconfig
stage refuses a symlinked kubeconfig) are deferred to the next release; see the
[findings tracker](../audits/mp23-findings.md).

## Validation

A green full gate and mutation sweep on the candidate, the native output and clone-free rehearsal
of each supported system, and the EP-172 rehearsal record moving a seeded local context from 0.6.4
to this release. The work intranet's upgrade and its admin API follow publication.
