# Nagare 0.30.0

The platform's Shōmei moves to v0.4.0.0, whose introspection reports `session_kind`, so a resource
server can tell an interactive sign-in from a machine token. An upgrade or apply no longer stops on
a slow rollout, a rerun of the release continues its own stopped transaction, and an
Application's service and workers can bind an app database.

## Added

- An Application's service and workers bind `appDatabases` through their accepted bindings, as
  buckets and key sets do: the runtime Secret's variables and an edge to it. The deploy review
  refused them with `app-database-not-bindable-from-application` although `app check` and render
  accepted them. A scheduled task of the service inherits the service's environment, so its own
  binding is still refused.

## Changed

- Shōmei v0.4.0.0 (mori://shinzui/shomei). `/oauth/introspect` reports `session_kind` on active
  access tokens; new delegated tokens carry `act` as `{"sub": …}`; token lifetimes are bounded;
  passkey enrollment requires discoverable credentials. It uses released `webauthn` 0.12 instead
  of a fork. Its seven migrations (0038–0044) add columns, indexes and write-time size checks,
  and 0043 records each existing session's provenance: a session with no recorded evidence of an
  interactive sign-in becomes a machine session, so its owner signs in again.
- A Deployment's readiness wait is Kubernetes' own rollout verdict (complete, or its progress
  deadline exceeded) instead of a fixed 180 s, and resuming such a wait waits for the rollout
  rather than refusing because the update changed the object. The lifecycle worker reading a
  large journal stopped the 0.29.0 upgrade this way.
- `just release-candidate` resumes the transaction its own earlier attempt left open, and its
  final check reports an application's or a deploy hook's unconverged scope instead of refusing
  on it.

## Upgrade notes

No config change is needed. The Shōmei, `nagare-access`, admin API and En images get new digests (En's
because shared Hackage libraries moved); the En source pin is unchanged. Shōmei 0.4 refuses to
start while a TOTP secret is in the legacy envelope; Nagare never enables TOTP, so no context holds
one. A user whose session migration 0043 reclassifies is asked to sign in again.

## Compatibility and rollback

`transitionsFrom` adds 0.29.0. Shōmei's migrations are forward-only; rolling back past them needs
the pre-upgrade `shomei-db` backup.

## Validation

A green full gate, the EP-172 upgrade rehearsal reading its seeded row back unchanged, and the work intranet running the candidate.
